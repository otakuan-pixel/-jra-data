# 中穴・大穴分析システム（anaba）

JRA平地の **中穴・大穴で3着内に来る馬** を、発走30分前の最新オッズで洗い出して報告するシステム。

| 区分 | 定義 |
|---|---|
| **中穴** | 6〜10番人気・単勝10〜30倍 |
| **大穴** | 10番人気以下・単勝30倍以上 |

10番人気は両方に入り、人気とオッズがずれる馬（多頭数の11番人気が25倍など）もいるので、**6番人気以下をオッズで分ける**（払戻はオッズで決まるため）。

- 発走30分前に、中穴・大穴の各馬について「推定3着内率（モデル）」と「オッズから見た3着内率（市場）」を比べ、複勝・単勝の期待値を出す
- 過去に好走した条件（競馬場・コース・距離帯・馬場・回り・人気薄での激走歴）と臨戦過程（間隔・叩き何戦目・距離変更・乗り替わり・ブリンカーなど）を馬ごとに列挙し、**その条件がすでに人気に織り込まれているか** を添える
- netkeiba の5代血統表からクロスを計算し、**奇跡の血量（3×4／4×3 ＝ 18.75%）** を判定する
- レポートは `reports/<日付>/` に保存し、GitHub の Issue にコメントで通知する（任意で Discord / Slack）
- 毎週、答え合わせ（`reports/ledger.md`）・再学習・血統の検証を自動で回す

データは [otakuan-pixel/jra2](https://github.com/otakuan-pixel/jra2) の成績データ（2021年〜・全10場・約27万頭）を使う。

## 分析でわかったこと（2026-11-26 時点）

詳細：[reports/research/README.md](reports/research/README.md)（区分ごとの条件表・モデル検証）、[reports/research/pedigree.md](reports/research/pedigree.md)（血統）

### 1. 「好走した馬の背景を調べる」だけでは不十分

好走馬だけを見ると「よくある条件」を拾ってしまう（生存者バイアス）。このシステムでは必ず
**同じ区分の凡走馬と比べ（リフト）**、さらに **オッズから期待される3着内数と比べる（A/E）**。

| 例（10番人気以下） | リフト | A/E | 意味 |
|---|--:|--:|---|
| 同コース（場・芝ダ・距離）で3着内あり | 1.43倍 | 0.90 | 好走馬によく見られるが、**市場はすでに織り込み済み（むしろ買われすぎ）** |
| 前走3着内 | 1.67倍 | 0.90 | 同上 |
| 前走 人気より大きく好走 | 1.22倍 | 1.03 | 目立たないぶん、わずかに過小評価 |
| 前走 4角から大きく追い上げ | 1.39倍 | 1.01 | 同上 |

→ 「過去に好走した条件に当てはまる馬」をそのまま拾うと、**的中率は上がるが回収率は上がらない**。

### 2. 中穴と大穴で、市場の歪み方が違う

| 全部買ったとき | 複勝回収率 | 単勝回収率 |
|---|--:|--:|
| 中穴（10〜30倍） | 80% | 84% |
| 大穴（30倍以上） | 62% | 62% |

大穴ほど「買われすぎ」が大きい（控除率20%を引いた平均80%より、さらに低い）。

### 3. モデル（ウォークフォワード検証：その年より前のデータだけで学習 → その年を予想）

確定オッズ。年ごとの回収率：

| 区分・選び方 | 券種 | 2023 | 2024 | 2025 | 2026 |
|---|---|--:|--:|--:|--:|
| 中穴 全部 | 単勝 | 84% | 79% | 85% | 88% |
| **中穴 ★（単勝期待値1.1以上）** | 単勝 | 103% | 86% | 91% | 106% |
| 大穴 全部 | 複勝 | 62% | 66% | 60% | 60% |
| **大穴 ★（複勝期待値0.9以上）** | 複勝 | 79% | 81% | 80% | 75% |
| 大穴 ☆（複勝期待値0.8以上） | 複勝 | 79% | 79% | 76% | 75% |

- **中穴は単勝**、**大穴は複勝** でモデルの上乗せが効く（大穴を単勝期待値で選ぶと、かえって悪い）
- 大穴は毎年安定して回収率を **60%前後 → 75〜81%** に引き上げる。中穴の単勝は100%を超える年もある（2023年103%・2026年106%）が、86%の年もあり、安定して100%は超えていない
- 閾値を上げるほど良くなるわけではない（件数が減り、推定の誤差も大きくなる）。印は区分ごとに毎年安定していた層に合わせている
- 本番は確定オッズではなく発走30分前のオッズで判定するので、検証より厳しくなる可能性がある → `reports/ledger.md` で本番の成績を毎週集計する

### 4. 奇跡の血量・血統

症例対照：同じレースの10番人気以下で、3着内に来た馬（1,777頭）と来なかった馬（3,221頭）の5代血統を、単勝オッズの差を補正して比べた（2024年5月〜2026年11月・1,628レース）。

| 特徴 | 好走馬での割合 | 凡走馬での割合 | オッズ比（オッズ補正） | 95%区間 |
|---|--:|--:|--:|---|
| 奇跡の血量（3×4／4×3） | 19.2% | 20.0% | 0.93 | 0.80〜1.08 |
| 　うちサンデーサイレンス 3×4 | 13.8% | 14.3% | 0.94 | 0.81〜1.11 |
| 　大穴（30倍以上）だけに絞る | 19.1% | 20.5% | 0.89 | 0.74〜1.03 |

- **奇跡の血量を持つ人気薄が3着内に来やすい、という傾向は見られない**（10番人気以下の約2割が持っていて、好走馬と凡走馬でほぼ同じ割合）
- 父 × 芝ダ（同じ馬場のレースの中での比較）は、50通りのうち6通りで差が出たが、偶然でも2〜3通りは出る数なので、まだ「効く血統」とは言えない
- レポートでは奇跡の血量を「血」印で引き続き表示し、検証結果（オッズ比と区間）を添える。データは毎週増やし、結果は [reports/research/pedigree.md](reports/research/pedigree.md) に自動で更新される

### 5. 調教データについて

調教タイムは JRA が公開しておらず、手元の成績データにも無い。代わりに **臨戦過程**（間隔・叩き何戦目・距離変更・芝ダ替わり・クラスの上げ下げ・乗り替わりと騎手の格・ブリンカー初装着・斤量・馬体重）と、**厩舎の人気薄での好走率** を使っている。

## 30分前レポートの見方

`reports/<日付>/<場>_<R>.md`（場コード：01札幌 02函館 03福島 04新潟 05東京 06中山 07中京 08京都 09阪神 10小倉）

レポートは「中穴」「大穴」の2つの欄に分けて出す。印と推奨券種は区分ごとに違う：

| 区分 | 印 | 基準 | 向いている券種 |
|---|:-:|---|---|
| 中穴 | ★ | 単勝期待値1.1以上 | 単勝 |
| 中穴 | ☆ | 複勝期待値0.9以上 | 複勝 |
| 大穴 | ★ | 複勝期待値0.9以上 | 複勝 |
| 大穴 | ☆ | 複勝期待値0.8以上 | 複勝 |
| 共通 | 血 | 期待値の印は無いが、奇跡の血量（3×4／4×3）を持つ | — |

期待値 ＝ 推定3着内率 × 複勝払戻の見込み（複勝）、推定勝率 × 単勝オッズ（単勝）。1.0 ＝ 回収率100%の見込み。

各馬の詳細には次を出す：
- 推定3着内率と、オッズから見た3着内率（何倍か）、推定勝率
- **市場が見落としがちな材料**（同じ区分の過去の馬で、A/Eが1.02以上かつ前半・後半とも1.0以上だった条件）
- **好走歴のある条件**（そのうち人気に織り込まれやすいものには注記）
- 臨戦過程、血統（父・母父・主なクロス・奇跡の血量と、その検証結果）
- 割高な人気馬（期待値が低い1〜5番人気）

期待値は推定値で、的中や利益を保証するものではない。

## 仕組み

```
[金・土・日 21:00]  anaba-prefetch   翌日のレース一覧（JRA出馬表）と出走馬の5代血統（netkeiba）を取得
[土日月 9:00-16:50] anaba-live       10分おき。発走25〜35分前のレースについて（遅れたら発走3分前まで）
                                       JRA出馬表（取消・乗り替わり・馬体重） + netkeibaの単勝/複勝オッズ・馬場
                                       → 特徴量（その日より前の情報だけ） → モデル → レポート → Issueにコメント
[火 21:00]          anaba-weekly     答え合わせ → 過去レースの血統収集 → 血統の検証 → 再学習と検証
```

| ファイル | 役割 |
|---|---|
| `anaba/data.py` | jra2 の成績データを読む |
| `anaba/entries.py` | JRA出馬表HTMLの解析（馬ID・父母・オッズ・馬体重・ブリンカー） |
| `anaba/features.py` | 特徴量（市場・前走/近走・スピード指数・ペース・条件別の好走歴・臨戦過程・騎手/調教師/生産者の人気薄での好走率） |
| `anaba/research.py` | 条件ごとのリフト・A/E・回収率（前半/後半の安定性つき） |
| `anaba/payout.py` | 複勝払戻（実測：成績PDF・netkeiba／推定：単勝オッズから） |
| `anaba/model.py` | LightGBM（市場モデル・穴モデル・勝率モデル）とウォークフォワード検証 |
| `anaba/pedigree.py` | 5代血統表の解析、クロス・奇跡の血量の判定、キャッシュ |
| `anaba/pedstudy.py` | 血統の症例対照検証 |
| `anaba/live.py` / `runner.py` / `report.py` | 発走前のデータ取得・採点・レポート |
| `anaba/settle.py` | 答え合わせ |

## 初期設定（GitHub）

1. Settings → Actions → General → Workflow permissions を **Read and write** にする（レポートのコミットと Issue 作成のため）
2. 通知：GitHub アプリでこのリポジトリを Watch（Issues）にしておくとスマホに届く
3. 任意：Discord / Slack に送るなら Settings → Secrets → Actions に `ANABA_WEBHOOK_URL` を登録
4. 任意：印の無いレースも通知するなら Settings → Variables に `ANABA_NOTIFY` = `all`
5. 手動実行：Actions → 「大穴レポート（発走30分前）」→ Run workflow（`race` に `05_11` などを入れると今すぐ）

## コマンド（手元で動かす場合）

```bash
pip install -r requirements.txt            # Python 3.13
git clone https://github.com/otakuan-pixel/jra2 ../otakuan-pixel/jra2   # または JRA2_REPO=<パス>
python -m anaba live --race 05_11 --no-notify   # 今日の東京11Rを今すぐ
python -m anaba replay --date 20261122 --race 05_11   # 過去のレースを再現（その日より前だけで学習し直す）
python -m anaba replay --date 20261121,20261122,20261123   # 開催日をまるごと再現 → reports/replay/
python -m anaba train                      # 学習一式（約3分）
python -m anaba backfill --max-requests 2000   # 過去レースの血統を集める（1.1秒間隔）
python -m anaba pedstudy                   # 血統の検証
python -m anaba settle                     # 答え合わせ
python -m pytest -q                        # オフラインの検査
```

## 注意

- netkeiba へのアクセスは1.1秒以上の間隔で、取得したものはキャッシュして二度取らない。個人の分析用途にとどめること
- 父・母父ごとの集計は、出馬表の履歴が2026年9月からしか無く「現役で残った馬」に偏るため、モデルには使っていない（毎週の取得で偏りが無くなったら追加する）
- 当日の馬場傾向（その日の前のレースの前残り・内有利）は、発走前の時点では成績データにまだ無いため使っていない
